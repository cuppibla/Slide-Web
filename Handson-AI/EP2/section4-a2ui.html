What Is A2UI?

Agent-to-User Interface — declarative JSON, not HTML, not text blobs

surfaceUpdate

Defines the component tree — flat array of typed components with unique IDs and property objects

// defines WHAT exists
{ "surfaceUpdate": {
    "surfaceId": "my-surface",
    "components": [...]
}}
beginRendering

Tells the frontend which component is root — triggers render

// tells WHERE to start
{ "beginRendering": {
    "surfaceId": "my-surface",
    "root": "card-id"
}}
Design Principles
  • Declarative — JSON blueprint, not executable code
  • Secure — no UI injection attacks possible
  • Framework-agnostic — same JSON for Angular, React, Flutter
  • LLM-friendly — structured for incremental generation
Critical Rule

validate_and_emit_a2ui must be called twice per surface — once for surfaceUpdate, once for beginRendering. Without beginRendering, nothing renders.

The 18 Component Primitives

Layout (7)
Column Row List Card Tabs Modal Divider

Children via {"explicitList": ["id1", "id2"]}

Display (5)
Text Image Icon Video AudioPlayer

Strings wrapped: {"literalString": "..."}

Input (6)
Button TextField CheckBox Slider MultipleChoice DateTimeInput

Booleans wrapped: {"literalBoolean": true}

Typed Value Wrappers — Never Raw Primitives

❌ "text": "Hello" — rejected

✅ "text": {"literalString": "Hello"} — valid

❌ "children": ["a","b"] — rejected

✅ "children": {"explicitList": ["a","b"]}

Two-Pass Validation

agents/skills/a2ui-rendering/tools.py — 436 lines

Pass 1 — Per-Component
  • Type against 18-primitive catalog
  • Required props per type
  • Typed value wrappers enforced
  • Duplicate ID detection
  • Collect all ID references
Pass 2 — Reference Resolution
  • Every reference must resolve to a known ID
  • Catches dangling pointers (Card → missing child)

Rendering Pipeline

From tool call to pixels — sub-100ms end to end

Agent calls validate_and_emit_a2ui(payload)
Two-pass validation → returns {"status":"success","a2ui": ...}
RedisDashLogPlugin extracts "a2ui" key → emits to Redis
Go gateway picks up → WebSocket broadcast to frontends
Frontend A2UI renderer maps components → native UI
A2UI updates stream as the agent runs — not after it finishes. The user sees progress, not silence.
