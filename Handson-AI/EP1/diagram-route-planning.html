Route Planning Architecture

The Spine & Sprout Algorithm

Deterministic 26.2-mile marathon route generation from raw GeoJSON

Phase 1
The Dijkstra Spine
Graph construction — Load GeoJSON LineString features into adjacency list
Haversine weights — Real geographic distance per edge from [lon, lat] coords
Sequential Dijkstra — Shortest non-overlapping path through all landmarks

Phase 2
The Bounded DFS Sprout
Guided heuristic — Prioritize nodes with most unvisited neighbors (avoid cul-de-sacs)
Deterministic tie-breaking — Sort by segment distance → then by exact coordinates
Exact interpolation — remaining / segment_length → interpolated [lon, lat] → exactly 26.2188 mi

Why Not an LLM?
This is a graph theory problem, not a natural language problem.

✗ Google Maps driving/walking directions can't handle closed roads or GeoJSON constraints

✗ Naive DFS gets trapped in cul-de-sacs

✗ LLMs can't guarantee exactly 26.2188 miles
