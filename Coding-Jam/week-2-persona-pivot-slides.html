The doctrine — 60-second recap

Three moves. Every project, every week.

📐 SPEC

Write before you code

A slim spec.md: out-of-scope list, behavioral rules, acceptance criteria. Hand it to your AI IDE. It holds what the spec holds.

📦 CONTEXT

Curate what AI reads

Everything the AI sees shapes its output. Give it the right context for the right task. Bad context = bad output, not a bad model.

🔍 CRITIC

Agents check agents

A second LLM (or process) checks the first. Today: the Synthesizer is your first soft critic. Week 4 builds the hard one.

"Spec is a lever. Context is fuel. The Critic finds the truth."

Why one agent isn't enough

Context contamination

"Think like 3 audiences" → the agent reads all 3 roles at once and quietly negotiates between them before generating. You get compromise, not independence.

Sequential bottleneck

Independent tasks forced to wait on each other. 3 parallel-able perspectives run in series = 3× unnecessary latency.

Single-lens anchoring

One agent with one instruction inevitably anchors on one frame. Complex decisions need genuinely different lenses.

Multi-agent solves this

  • Isolated contexts — no perspective contaminates another
  • Simultaneous execution — 3 agents at once, not in series
  • Single focused role per agent — specialization > generalism
  • Synthesizer finds structure across all outputs

The key insight

"Orchestration is a design decision,
not a technical detail."

Three workflow patterns in ADK

Pick based on dependency structure.

SequentialAgent

A → B → C. Each waits for the previous to finish.

Use when: Step N needs step N-1's output.

Example: Search → Summarize → Rank

ParallelAgent

A, B, C run simultaneously. All finish before next stage.

Use when: Agents are independent — no runtime dependency.

Critical: Each sub-agent needs a unique output_key.

Custom BaseAgent

You write Python logic + call LLM directly. Full control.

Use when: You need Python to bridge agents or build dynamic prompts.

Example: Synthesizer — reads 3 keys, builds prompt

Most real workflows are hybrids. Persona Pivot: SequentialAgent wraps ParallelAgent → SynthesizerAgent. Sequential for ordering, Parallel for independence, Custom to bridge them.

ParallelAgent deep dive 📦 Context

from google.adk.agents import LlmAgent, ParallelAgent

# Each sub-agent writes to its OWN unique key
skeptic = LlmAgent(
    name="skeptic_agent",
    model="gemini-2.0-flash",
    instruction="You are a skeptic...",
    output_key="skeptic_perspective", # unique
    tools=[],
)
enthusiast = LlmAgent(
    name="enthusiast_agent",
    model="gemini-2.0-flash",
    instruction="You are an enthusiast...",
    output_key="enthusiast_perspective",
    tools=[],
)

# All 3 run at the same time
parallel = ParallelAgent(
    name="parallel_perspectives",
    sub_agents=[
        skeptic, enthusiast, pragmatist
    ],
)
# After: session.state has all 3 keys

Key isolation insight

Sub-agents see state as it was when ParallelAgent started. They cannot read sibling outputs — they're already running. Isolation by architecture, not convention.

The Synthesizer pattern 🔍 Critic

from google.adk.agents.base_agent import BaseAgent
from google.adk.agents.invocation_context import (
    InvocationContext)
from google.adk.events import Event
from typing import AsyncGenerator
from google import genai
from google.genai import types

class SynthesizerAgent(BaseAgent):
    model_name: str = "gemini-2.0-flash"

    async def _run_async_impl(
        self, ctx: InvocationContext
    ) -> AsyncGenerator[Event, None]:

        # 1. Read all 3 perspectives from state
        skeptic  = ctx.session.state.get(
            "skeptic_perspective", "")
        enthusiast = ctx.session.state.get(
            "enthusiast_perspective", "")
        pragmatist = ctx.session.state.get(
            "pragmatist_perspective", "")

        # 2. Build synthesis prompt dynamically
        prompt = (f"SKEPTIC: {skeptic}\n"
                  f"ENTHUSIAST: {enthusiast}\n"
                  f"PRAGMATIST: {pragmatist}\n\n"
                  "Find tensions and agreements.")

        # 3. Call LLM directly
        client = genai.Client()
        resp = client.models.generate_content(
            model=self.model_name, contents=prompt)

        # 4. Yield the Event
        yield Event(
            invocation_id=ctx.invocation_id,
            author=self.name,
            content=types.Content(role="model",
                parts=[types.Part(text=resp.text)]),
        )

Why custom, not LlmAgent?

  • Pull specific state keys in Python
  • Validate all 3 exist before calling LLM
  • Build prompts using actual audience labels
  • LlmAgent = static instruction. Custom = Python + LLM.

This IS a critic

Synthesizer reviews other agents' outputs and finds structure. Soft critic = finds tensions. Hard critic (Week 4) = validates correctness. Same pattern, different purpose.

"An agent reviewing agents is a critic."

Required output

Per spec.md: ≥1 tension + ≥1 agreement + synthesis + key question. Structured, not just a summary.

ADK sub-agent architecture

from google.adk.agents import SequentialAgent
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types

# SequentialAgent wraps: [Parallel → Synthesizer]
root_agent = SequentialAgent(
    name="persona_pivot",       # adk web looks for this
    sub_agents=[
        parallel_perspectives,  # stage 1
        synthesizer_agent,      # stage 2
    ],
)

# Session — no persistence (per spec.md)
session_service = InMemorySessionService()

runner = Runner(
    agent=root_agent,
    session_service=session_service,
    app_name="persona_pivot",
)

# Create session + run
session = session_service.create_session(
    app_name="persona_pivot", user_id="user_1")

async for event in runner.run_async(
    user_id="user_1",
    session_id=session.id,
    new_message=types.Content(
        role="user",
        parts=[types.Part(text="Idea: ...")],
    ),
):
    print(event.author, event.content)

Context isolation principle 📦 Context

Without isolation

Skeptic runs first. Enthusiast reads Skeptic's output and softens. Pragmatist reads both and plays it safe. Three voices that quietly negotiated toward the center. The independence you wanted never existed.

"Sequential perspectives are secretly correlated."

With ParallelAgent isolation

All 3 agents start simultaneously from the same state. None can read what the others are writing — they're already running. Genuine independence enforced by timing.

"Architecture as policy."

WHAT EACH AGENT SEES

skeptic_agent sees: • Its own instruction (role contract) • User's original message • session.state at start (empty) • ✗ Does NOT see enthusiast/pragmatist enthusiast_agent sees: • Its own instruction (different contract) • Same user message • Same empty starting state • ✗ Does NOT see skeptic/pragmatist pragmatist_agent sees: • Its own instruction • Same user message, same empty state • ✗ Does NOT see skeptic/enthusiast synthesizer_agent (runs after all 3): • All 3 keys now in session.state • ✓ ONLY agent that sees everything

Role contracts as specs 📐 Spec

# The Skeptic's role contract
skeptic = LlmAgent(
    name="skeptic_agent",
    instruction="""
You are a seasoned professional calibrated
by watching promising ideas fail.

Focus ONLY on:
  risks, failure modes, unproven assumptions,
  resource obstacles, historical failures.

DO NOT discuss:
  upside, opportunity, emotional appeal.
  That is not your role.

End with:
  "Change my mind: [one condition]"

Format: 3-5 direct sentences.
Lead with your biggest concern.
    """,
    output_key="skeptic_perspective",
)

# Change this instruction →
#   Only the Skeptic changes.
#   Enthusiast: unchanged.
#   Pragmatist: unchanged.
#   Synthesizer: unchanged.
# Each role contract is an isolated lever.

What a good role contract includes

  • Who the agent IS — worldview, biases
  • What they consider (scope)
  • What they DON'T consider (explicit out-of-scope)
  • Tone and format
  • Ending convention (creates consistency)

Why the out-of-scope list matters

LLMs default to balance. Without explicit prohibition, the Skeptic quietly mentions "but there's potential here." The out-of-scope list is the spec that prevents drift.

"Spec prevents drift. Drift corrupts perspective."

Demo recap — the dramatic moment

What the Synthesizer surfaced — and why it couldn't come from a single agent.

The idea

"Replace the weekly all-hands with a 5-minute async video update tool"

Audiences: Engineering team · Executive leadership · Customer sales

Tension found

Executives need real-time morale signals. Engineering wants async autonomy. A recorded video cannot replace a live read of the room. These are in genuine conflict.

Agreement found

All three perspectives agreed: the 9am Monday slot is the real problem, not the format. Async solves the time constraint — not the information-flow constraint.

Key question surfaced

"Can a video update include a required flag/reaction mechanism that gives executives early-warning capability?"

Not visible before the parallel run.

Doctrine moments in today's build

📐 Spec moment

Each sub-agent has its own role contract. Edit the Skeptic's instruction → only the Skeptic changes. Others unaffected.

"Spec is a lever. Each instruction is a control surface."

Each sub-agent gets only its own instruction + user input. Context isolation is enforced by architecture, not by telling agents to "ignore" each other.

"What the agent doesn't see matters as much as what it does."
