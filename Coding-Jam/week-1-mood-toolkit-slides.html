What is Vibe Coding?

Definition

Building software by describing intent to an AI IDE. You direct; it writes, runs, and debugs the code. No boilerplate. No syntax lookup.

The 2026 upside

10× output for solo builders. Functional prototypes in hours. Code your non-coding teammates can actually read.

⚠ New failure modes
🌀 Drift — AI builds more than asked, or the wrong version of what was asked.
🪣 Bloat — AI adds dependencies, abstractions, and features you'll never use.
🤝 Trust collapse — You can't maintain what you don't understand.
The question isn't "can I vibe code?"
It's "can I vibe code reliably?"

📋 Spec — today's focus

Write spec.md before coding. Contains: out-of-scope list, behavioral rules, acceptance criteria. This is the AI's contract — it can only refuse features it knows are excluded.

Spec → Context → Critic

Failure mode #1

Why Drift Happens

LLMs complete patterns. If your prompt implies a larger system, the model builds the larger system.

✅ You asked: "Build me a simple email reply agent."
⚠ You got: Full inbox triage system with labels, auto-archive, priority scoring, and an unsubscribe scanner — 4× what was needed.
Why it happens

"Reply agent" → the model's training contains many reply agents that also manage inboxes. Pattern completion kicks in silently.

How spec prevents it

spec.md out-of-scope list explicitly says "no inbox triage, no labels, no auto-archive." The AI can only refuse what it knows is excluded.

Rule: if the AI added something you didn't ask for, your spec didn't say "no" loud enough.

Pillar 1 deep dive

spec.md in Practice

spec.md contains

❌Out-of-scope list — explicit "no X" items the IDE must refuse
📏Behavioral rules — tone, format, hard constraints
✅Acceptance criteria — falsifiable: "returns 4 items," "response <5s"

Does not contain: architecture, library choices, database schema — those go in plan.md

## Out of Scope
- ❌ Auto-send: no email/SMS of toolkit
- ❌ Multi-agent: one LlmAgent only
- ❌ Persistent memory: no database
- ❌ No SendGrid / Twilio / smtplib

## Behavioral Rules
- MUST return song + movie + action every time
- NEVER fabricate Spotify or event URLs
- Tone: warm and cozy, never clinical

## Acceptance Criteria
- AC-1: Deploy URL returns HTTP 200
- AC-2: Complete toolkit for any mood input
- AC-6: Response time under 5 seconds

The framework

Google ADK

Agent Development Kit — open-source Python framework for building, evaluating, and deploying AI agents. v1.32.0 · May 2026

LlmAgent — the core building block. Wraps a Gemini model with an instruction string + optional tools.
Built-in tools — google_search, code execution, and more. Import, don't write.
Runner + Sessions — manages turns, state, multi-turn context. 
from google.adk.agents import LlmAgent
from google.adk.tools import google_search

root_agent = LlmAgent(
    name="mood_toolkit_agent",
    model="gemini-2.5-flash",
    instruction=INSTRUCTION,
    tools=[google_search],
)

That's the entire agent. Really.

Tools > raw LLM knowledge

The google_search Built-in Tool

Why tools matter

Gemini's training data has a cutoff. It doesn't know the café that opened last month. google_search gives the agent real-time web access — on demand, not always.

How the agent decides

"I'm in Brooklyn" → agent calls google_search for real places. "I feel tired" → agent already knows songs and movies. No search needed.

⚠ Don't combine google_search with output_schema — they conflict in ADK. 
from google.adk.tools import google_search

root_agent = LlmAgent(
    name="mood_toolkit_agent",
    model="gemini-2.5-flash",
    instruction=INSTRUCTION,
    tools=[google_search],  # just add it
)

Built-in = import it, not write it.

From localhost to the world

Cloud Run Deployment

What Cloud Run is

Fully managed serverless containers on Google Cloud. Scales to zero when idle (free!), auto-scales under load. Always-on public HTTPS URL. Zero Dockerfile writing.

What ADK does for you

Packages code → builds container → pushes to Artifact Registry → deploys. One command, no Docker knowledge required.

Prerequisites: gcloud CLI authenticated · GCP project with billing · requirements.txt 
# Test locally first
adk web

# One-command deploy
adk deploy cloud_run \
  --project=YOUR_PROJECT_ID \
  --region=us-central1 \
  week-1-mood-toolkit/

# Output:
# ✓ Build complete
# ✓ Image pushed to Artifact Registry
# ✓ Service deployed to Cloud Run
# → https://mood-toolkit-xxxx.run.app
