The Las Vegas Problem

Why you can't just call Google Maps

  • Route must use approved city streets only
    GeoJSON from city permit — no arbitrary paths
  • Driving directions: blocked
    One-way rules don't apply when roads are closed
  • Walking directions: blocked
    Routes through buildings, wrong surface type
The Constraint
Generate a valid 26.2188-mile loop over the Las Vegas road network from raw GeoJSON.

This is a graph theory problem, not a directions API problem.

The Spine and Sprout Algorithm

agents/planner/skills/gis-spatial-engineering/scripts/tools.py

Phase 1 — Dijkstra Spine
  • Build adjacency graph from GeoJSON LineString features
  • Haversine-weighted edges (real geographic distance)
  • Dijkstra: Las Vegas Sign → Stadium → Sphere → …
Phase 2 — Bounded DFS Sprout
  • Extend from spine endpoint until 26.2188 mi
  • Degree heuristic: prefer connected nodes
  • Tie-break: by distance, then coordinates
  • Linear interpolation → exactly 26.2188 mi
✓ Fully deterministic ✓ Regression-tested ✓ Zero LLM involvement

LLM vs Code Decision Framework

When to reach for an LLM
  • Open-ended synthesis:
    "Write a race narrative"
  • Multi-preference constraint satisfaction:
    "Balance safety, community, and revenue"
  • Adaptive response to novel inputs
When to write deterministic code
  • Mathematical precision required
    26.2188 mi exactly
  • Fixed tool-call sequences
    spawn → collect → fire
  • Speed + cost at scale
    1,000 × N calls = $$$
  • Testability is non-negotiable
If you can write a unit test that fully specifies the expected output, write code. Otherwise, use the LLM.

Simulator Agent Structure

pre_race → spawn runners, start collector
LoopAgent("race_engine") → up to 200 ticks
tick → advance_tick → check_race_complete
post_race → compile results, stop collector
The Trick

before_model_callback intercepts every LLM call. The model is never invoked.

# The LLM never fires
tick_agent = LlmAgent(
    name="tick",
    model=resilient_model(
        "gemini-flash-lite"),
    before_model_callback=tick_callback,
)

Why Keep It as an "Agent"?

Even when the LLM is replaced, the agent gives you:

  • Lifecycle — ADK manages session state, callbacks, error handling
  • A2A interface — same API regardless of internal implementation
  • Telemetry — RedisDashLogPlugin fires automatically
  • Plugin compatibility — attach without code changes
  • Swappability — swap autopilot ↔ LLM runner with one env var

runner_autopilot/agent.py — the entire override

# The entire override
def get_agent():
    agent = get_base_agent()
    agent.before_model_callback \
        = autopilot_callback
    return agent

The agent boundary is about interface, lifecycle, and observability — not about whether an LLM is running inside.
