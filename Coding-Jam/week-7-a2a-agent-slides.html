Brief background context

MCP: Agent ↔ Tool

🤖 AI Agent
has reasoning
MCP  ·  tool call / result
🔧 Tool
no reasoning

What MCP solves

Any AI client can use any MCP-compatible tool. No custom integration per agent+tool pair. Standardized tool-calling protocol.

What a "tool" is

Stateless function. A database lookup, an API call, a file reader. No LLM inside. No agent loop. No opinions.

MCP = tool protocol

But what if the "tool" is itself an intelligent agent that thinks back?

New here? MCP is the prior week's topic — just know: it connects agents to dumb tools. Today we go further.

The next level

What if the other side thinks back?

🤖 Agent A
reasoning
A2A  ·  tasks / artifacts
🤖 Agent B
reasoning

Both sides have an LLM. Both sides have an agent loop. Both sides have agency.

Why MCP doesn't work here

MCP assumes the other side is a dumb function. Agent B has its own context, tools, and multi-step reasoning. MCP has no model for that.

What A2A adds

Task lifecycle management. Long-running async work. Discovery via Agent Cards. A shared protocol for two full agents to collaborate.

A2A Protocol

What it defines

Discovery

Any agent finds any other agent's capabilities by fetching /.well-known/agent-card. No prior handshake needed.

Message format

JSON-RPC 2.0. Method: tasks/send. Content wrapped in a Task envelope with lifecycle tracking.

Task lifecycle

Tasks have states: submitted → working → completed. Long-running agents signal progress incrementally.

Open standard

Contributed by Google to the Linux Foundation, April 2025. 150+ org contributors. Works across any language, any cloud.

a2a-protocol.org · github.com/a2aproject/A2A

Agent cards

Anatomy of a card

"name": "Trip Idea Generator",
"description": "Generates 3-day travel...",
"url": "https://agent.run.app",
"version": "1.0.0",
"defaultInputModes": ["text/plain"],
"skills": [{
"id": "generate_itinerary",
"name": "Generate Itinerary",
"examples": ["relaxed, $150/day"]
}],
"authentication": { "schemes": ["none"] }

Identity

name, description, version, provider

Skills (capabilities)

What the agent can do. Each skill has id, name, description, examples.

I/O contracts

defaultInputModes + outputModes — MIME types

Auth

authentication.schemes: ["none"] = public agent

Served at: https://your-agent.run.app/.well-known/agent-card

Spec pillar — the deepest expression

Agent Card = Spec

The Agent Card is spec.md — but public, machine-readable, and cross-org.

Edit it → redeploy → the world sees the updated spec. Immediately.

A spec.md file (traditional)

Human-readable. Project-internal. Your team reads it. Defines constraints for this sprint.

Scope: your team

Agent Card (today)

Machine-readable. Public. Any agent, any org, any cloud can discover your capabilities at runtime.

Scope: the entire A2A ecosystem

A vague description field = a broken contract. Future agents can't decide whether to call you. The Spec pillar, at protocol scale.

Why A2A matters

M×N

With A2A

M+N

Same value MCP gave for tools — now applied to full agents.

ADK + A2A

Exposing an agent via A2A

from google.adk.agents import LlmAgent
from google.adk.a2a.utils.agent_to_a2a import to_a2a
import uvicorn

# 1. Build your agent (same as always)
agent = LlmAgent(
    name="trip-idea-generator",
    model="gemini-2.0-flash",
    description="Generates 3-day itineraries...",
    instruction="You are a travel planner..."
)

# 2. Wrap with A2A — one line
#    ✦ Creates a FastAPI app
#    ✦ Auto-generates Agent Card
#    ✦ Handles JSON-RPC 2.0 routing
#    ✦ Serves /.well-known/agent-card
app = to_a2a(agent)

# 3. Run
if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8080)

What to_a2a() gives you

Complete A2A server. Agent Card at /.well-known/agent-card. Task routing. JSON-RPC 2.0. All automatic.

Deploy

gcloud run deploy my-agent \
  --source . \
  --allow-unauthenticated \
  --port 8080

Test

The critic

A2A Inspector

What it is

Official protocol-level debugger. NOT a chatbot — a compliance validator and wire-level inspector.

github.com/a2aproject/a2a-inspector

Get it

npx @a2a/inspector

Connect

Paste Cloud Run URL → Inspector fetches /.well-known/agent-card automatically

Agent Card panel

Fetches and displays your card. Shows spec compliance issues.

Chat panel

Send messages. Watch them get wrapped in A2A Task envelopes.

Debug console ← the key panel

Raw JSON-RPC 2.0. See tasks/send, status.state, artifacts. The protocol, naked.

Compliance panel

Validates Agent Card fields. Finds spec violations your app tests miss.
