This is A2UI: your agent returns declarative JSON, not HTML. The renderer builds native components from it. Same agent — different context — different UI.

The problem with HTML

Why NOT just return HTML?

🚨

XSS & Security

An LLM generating HTML can produce <script> tags, phishing links, and layout bombs. You can't reliably sanitize all of it.

🖼️

iframe Sandboxing is Ugly

iframes are heavy, inconsistent across platforms, and can't access your app's design system, fonts, or theme tokens.

📐

Fixed UI = Missed Point

If the layout never changes — only the text — it's a template engine, not generative UI. A2UI generates a different component tree per response.

A2UI's answer: declarative JSON + client-controlled catalog + native rendering.

The solution

A2UI: Declarative JSON, Native Rendering

Google's open protocol. pip install a2ui-agent-sdk — on PyPI, v0.9.

🧩

Declarative JSON

Agent says what, not how. Component tree, not rendering code.

🛡️

Catalog = Allowlist

Only known components render. Unknown types are rejected. Zero injection risk.

🌐

Native Rendering

Same JSON → web (Lit), mobile (Flutter), desktop. Client keeps its design system.

// What the agent sends
{ "version": "0.9",
  "components": [{ "type": "Card", "props": { "backgroundColor": "#FFFBEB" }, "children": [
    { "type": "Heading", "props": { "text": "You're glowing ✨", "color": "#F59E0B" }},
    { "type": "Button", "props": { "label": "Start something exciting" }}
  ]}]}
// Renderer builds native Lit / Flutter / Angular components

The SDK

A2uiSchemaManager — Three Jobs

The core class in a2ui-agent-sdk.

①

Load the Catalog

Loads 18 BasicCatalog components with their schemas, required props, and validation rules.

②

Generate the Prompt

generate_system_prompt() teaches the LLM valid A2UI JSON format with schema + few-shot examples.

③

Validate Output

validate() rejects unknown components, missing props, or HTML injection before it reaches the renderer.

from a2ui.basic_catalog.provider import BasicCatalog
from a2ui.core.schema.manager import A2uiSchemaManager

catalog_config = BasicCatalog.get_config()
schema_manager = A2uiSchemaManager(catalogs=[catalog_config])

# ② LLM gets the full component spec as its system prompt
system_prompt = schema_manager.generate_system_prompt(role_description="mood card agent")

# ③ Validate before returning — the Critic step
validated = schema_manager.validate(agent_output_json)
The doctrine

Spec · Context · Critic — All Three at Once

This week they stop being separate ideas and start being one system.

📋 Spec

The catalog IS the spec.

Not a document you might ignore. A machine that rejects non-compliant output. The agent cannot ship a component that isn't in the catalog.

🌊 Context

Mood shapes the UI layout.

Input = context = output shape. "anxious" → Alert with grounding steps. "calm" → minimal Card with Avatar. Context is structural, not decorative.

🔍 Critic

Validation before render.

schema_manager.validate() runs before any JSON leaves the agent. Bad output fails loudly here — not silently at render time.

The key insight: In previous weeks, the spec was a document. This week, the spec is enforced by a machine. A spec that can't be violated at runtime is more powerful than one that can only be violated accidentally.
