Why Not Store Full Transcripts?

🏔️
Lost in the Middle
LLMs attend poorly to content buried in very long contexts. Old transcripts degrade response quality.
💸
Unbounded Cost
Every stored message gets re-injected into future context windows. 10 sessions × 20 turns = 200 messages in context.
🔁
Redundant Replay
"Nice to meet you!" replayed every session. Pleasantries crowd out the actual signal.
🧠
Selection Forces Reasoning
Deciding what's worth keeping is intelligence. "What matters?" is a harder, better question than "log everything."

EXTRACTION PROMPT:
"Given this conversation, identify facts about the USER worth remembering long-term.

Rules:
- Only extract facts ABOUT THE USER (not the pet's responses)
- Categories: preference | relationship | situation | identity
- Skip pleasantries, filler, hypotheticals
- Be SELECTIVE: a 10-turn conversation → 2-4 facts, not 10
- Confidence: 1.0 = stated directly, 0.8 = strongly implied

Return ONLY valid JSON:
{
  'facts': [{'fact_text': '...', 'category': '...', 'confidence': 0.0-1.0}],
  'interaction_summary': '...',
  'sentiment': 'positive|neutral|negative'
}"

The extractor is a second, silent LLM running after every turn

SQLite in Cloud Run

The simplest persistent memory that works — and the constraint that explains the architecture.

Why SQLite works here
  • Zero config — it's just a file on disk
  • No managed service, no auth setup
  • Perfect for single-user personal agents
⚠️ The one critical constraint
--max-instances=1  # critical

Two instances = two files = split memory. One instance = one file = consistent memory.

Upgrade path: one line change
db_url = "sqlite+aiosqlite:///./pet.db"          # SQLite (today)
db_url = "postgresql+asyncpg://user:pw@host/db"  # Cloud SQL (upgrade)
gcloud run deploy pet-companion --source . \
  --max-instances=1 \
  --set-env-vars GOOGLE_API_KEY=$GOOGLE_API_KEY

The Upgrade Path: Cloud SQL

SQLite gets you to the moment. Cloud SQL gets you to production — and cross-device.

SQLite — MVP
  • ✅ Zero config
  • ✅ Single-user personal agents
  • ✅ --max-instances=1
  • — One instance only
  • — No cross-device sync
Cloud SQL — production
  • ✅ Multi-instance Cloud Run
  • ✅ Cross-device — open on phone
  • ✅ Backup, scaling, replication
  • ✅ Same ADK code, one URL change
  • — Costs ~$10/mo minimum
