The Loop That Actually Works

1. Write the test first
2. Ask the model to implement it
3. Run the test suite
4. Review the diff — not the conversation
5. Commit or iterate
Review the diff, not the conversation. You're a code reviewer, not a prompt engineer.
Guardrails in this codebase
  • make test — Python + Go + TS, all offline
  • Pre-commit hooks — lint, type check, format
  • Route determinism regression tests
  • Agent card schema validation

Agentic Engineering vs Vibe Coding

Vibe CodingAgentic Engineering
GoalMake something that looks like it worksMake something that provably works
Test suiteOptional / afterthoughtRequired / written first
Model roleWrite all the codeImplement to spec
ReviewTrust the modelReview every diff
Failure modeWorks in demo, breaks in prodCaught by tests before shipping
Skill neededPrompt creativitySoftware engineering + AI fluency
AI assistance raises the ceiling on what one developer can build.
A test suite raises the floor on what actually ships.

The Skills System

skills/
├── gis-spatial-engineering/
│   ├── SKILL.md   ← LLM instruction
│   └── tools.py   ← Python functions
├── directing-the-event/
├── mapping/
├── insecure-financial-modeling/
└── secure-financial-modeling/
Pattern: SKILL.md + tools.py
  • SKILL.md — what the LLM sees
  • tools.py — what actually runs
  • Loaded on demand — context stays lean
Example: gis-spatial-engineering
  • Contains Spine and Sprout route algorithm
  • Haversine, Dijkstra, interpolation
  • Pure Python, fully testable
  • Zero LLM involvement
The skills directory is where the real engineering lives. The LLM is the orchestrator; the skills are the workers.
